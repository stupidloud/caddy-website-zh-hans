# Welcome to Caddy

Caddy는 Go 언어로 작성된 강력하고 확장 가능한 플랫폼으로, 사이트, 서비스 및 애플리케이션을 서비스하는 데 사용됩니다. Caddy를 처음 사용하신다면, 이제 웹을 서비스하는 방식이 완전히 바뀔 것입니다.

## Introduction

대부분의 사람들은 Caddy를 웹 서버나 프록시로 사용하지만, 핵심적으로 Caddy는 서버들을 위한 서버입니다. [필수 모듈](/docs/modules/)을 사용하면 Caddy는 오래 실행되는 어떤 프로세스의 역할도 수행할 수 있습니다!

구성은 [Caddy의 API](/docs/api)를 통해 동적으로 이루어지며 내보낼 수도 있습니다. 설정 파일이 필수는 아니지만 여전히 사용할 수 있으며, 사람들이 Caddy를 구성할 때 가장 선호하는 방식은 [Caddyfile](/docs/caddyfile)을 사용하는 것입니다. 설정 문서의 형식은 [구성 어댑터(config adapters)](/docs/config-adapters)를 통해 여러 가지 형태를 취할 수 있지만, Caddy의 기본 구성 언어는 [JSON](/docs/json/)입니다.

Caddy는 모든 주요 플랫폼용으로 컴파일되며 런타임 종속성이 없습니다.


## First time?

문제없습니다! **경험에 관계없이 _모든 사용자_ 가 우리의 [시작하기 가이드](/docs/getting-started)를 읽어보시기를 권장합니다.** 이 가이드는 여러분의 새로운 웹 서버에 대한 균형 잡힌 시각을 제공할 것이며, 앞으로 계속 학습해 나가는 데 매우 유용할 것입니다.

시간이 몇 분밖에 없고 즉시 실행해야 한다면, 우리의 [빠른 시작(quick starts)](/docs/quick-starts) 중 하나를 시도해 보세요.

특정 예제와 같이 더 확장된 콘텐츠를 보려면 [커뮤니티 위키](https://caddy.community/c/wiki/13)를 확인하고 기여해 보세요!

무작위 블로그나 Q&A 게시판에서 명령을 실행하거나 설정 조각을 복사하는 것보다, Caddy를 [설치](/docs/install), [구성](/docs/caddyfile) 및 [실행](/docs/command-line)할 때는 이러한 공식 리소스를 따르는 것을 권장합니다. 우리의 자료가 일반적으로 훨씬 정확하고 최신 정보임을 알게 되실 겁니다. 또한 서버가 어떻게 작동하는지 이해할 수 있도록 직접 구성을 작성해보는 것을 권장하며, 이를 통해 나중에 문제가 발생했을 때 더 쉽게 해결할 수 있게 될 것입니다.

하지만 무엇을 하시든 새로운 웹 서버를 즐겁게 사용하시길 바랍니다. Caddy는 여러분이 사용해 본 다른 어떤 서버 소프트웨어와도 다른 경험을 선사할 것입니다!


## Getting help

Caddy 사용에 도움이 필요하다면, [커뮤니티 포럼](https://caddy.community)에 정중하게 질문해 주세요. 기꺼이 도와드리겠습니다. 우리가 부탁드리는 것은 도움말 템플릿을 가능한 한 자세히 작성하고, 다른 사람들을 도움으로써 보답해 달라는 것뿐입니다. 우리는 항상 더 많은 조력자를 필요로 합니다.

Caddy에서 버그를 확실히 식별했거나 특정 기능 요청이 있는 경우에만 [이슈 트래커](https://github.com/caddyserver/caddy/issues)를 사용해 주세요.

이 웹사이트는 [GitHub에서 유지 관리됩니다](https://github.com/caddyserver/website). 개선 사항을 제출하려면 이슈를 열거나 풀 리퀘스트를 제출해 주세요.

우리 커뮤니티에 참여해 주셔서 감사합니다! Caddy가 여러분에게 많은 도움이 되기를 바랍니다.
