# fs

Задает, какая файловая система должна использоваться для выполнения file I/O.

Это может позволить подключиться к удаленной файловой системе в cloud, к базе данных с file-like interface или даже читать файлы, встроенные в binary Caddy.

Сначала нужно объявить имя файловой системы с помощью [глобальной опции `filesystem`](/docs/caddyfile/options#filesystem), затем можно использовать эту директиву, чтобы указать, какую файловую систему применять.

Эта директива часто используется вместе с [директивой `file_server`](file_server) для отдачи статических файлов или с [директивой `try_files`](try_files), чтобы выполнять rewrites на основе существования файлов. Обычно также используется с [директивой `root`](root), чтобы задать root path внутри файловой системы.


<a id="syntax"></a>
## Синтаксис

```caddy-d
fs [<matcher>] <filesystem>
```

<a id="examples"></a>
## Примеры

Использование файловой системы с именем `foo` через воображаемый module `custom`, которому может требоваться аутентификация:

```caddy
{
	filesystem foo custom {
		api_key abc123
	}
}

example.com {
	fs foo
	root /srv
	file_server
}
```

Чтобы отдавать только изображения из файловой системы `foo`, а остальное — из файловой системы по умолчанию:

```caddy
example.com {
	fs /images* foo
	root /srv
	file_server
}
```
