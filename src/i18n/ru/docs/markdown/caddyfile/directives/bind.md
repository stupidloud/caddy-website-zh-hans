# bind

Переопределяет интерфейс, к которому должен привязаться socket сервера.

Обычно listener привязывается к пустому (wildcard) интерфейсу. Однако можно принудительно привязать listener к другому имени хоста или IP. Эта директива принимает только host, но не port. Порт определяется [адресом сайта](/docs/caddyfile/concepts#addresses) (по умолчанию `443`).

Обратите внимание, что несогласованная привязка сайтов может привести к непредвиденным последствиям. Например, если два сайта на одном порту разрешаются в `127.0.0.1`, и только один из них настроен с `bind 127.0.0.1`, то доступен будет только один сайт, потому что другой привяжется к порту без конкретного host; ОС выберет более конкретно совпадающий socket. (Virtual hosts не разделяются между разными listeners.)

`bind` принимает [сетевые адреса](/docs/conventions#network-addresses), но не может включать port.


<a id="syntax"></a>
## Синтаксис

```caddy-d
bind <hosts...>
```

- **&lt;hosts...&gt;** — список host interfaces, к которым нужно привязать listener. 


<a id="examples"></a>
## Примеры

Чтобы сделать socket доступным только на текущей машине, привяжите его к loopback interface (localhost):

```caddy
example.com {
	bind 127.0.0.1
}
```

Чтобы включить IPv6:

```caddy
example.com {
	bind 127.0.0.1 [::1]
}
```

Чтобы привязаться к `10.0.0.1:8080`:

```caddy
example.com:8080 {
	bind 10.0.0.1
}
```

Чтобы привязаться к Unix domain socket по пути `/run/caddy`:

```caddy
example.com {
	bind unix//run/caddy
}
```

Чтобы изменить права файла так, чтобы запись была доступна всем пользователям ([по умолчанию](/docs/conventions#network-addresses) используется `0200`, то есть запись доступна только владельцу):

```caddy
example.com {
	bind unix//run/caddy|0222
}
```

Чтобы привязать один домен к двум разным интерфейсам с разными ответами:

```caddy
example.com {
	bind 10.0.0.1
	respond "One"
}

example.com {
	bind 10.0.0.2
	respond "Two"
}
```
