# log

Включает и настраивает журналирование HTTP-запросов, также известное как журналы доступа.

<aside class="tip">

Чтобы настроить runtime-журналы Caddy, используйте вместо этого [глобальную опцию `log`](/docs/caddyfile/options#log).

</aside>


Директива `log` применяется к именам хостов блока сайта, в котором она указана, если это не переопределено поддирективой `hostnames`.

После настройки по умолчанию журналируются все запросы к сайту. Чтобы условно исключать некоторые запросы из журналирования, используйте [директиву `log_skip`](log_skip).

Чтобы добавлять пользовательские поля в записи журнала, используйте [директиву `log_append`](log_append).

По умолчанию заголовки с потенциально чувствительной информацией (`Cookie`, `Set-Cookie`, `Authorization` и `Proxy-Authorization`) в журналах доступа записываются как `REDACTED`. Это поведение можно отключить глобальной серверной опцией [`log_credentials`](/docs/caddyfile/options#log-credentials).


<a id="syntax"></a>
## Синтаксис

```caddy-d
log [<logger_name>] {
	hostnames <hostnames...>
	no_hostname
	output <writer_module> ...
	format <encoder_module> ...
	level  <level>
	sampling {
		interval   <duration>
		first      <number>
		thereafter <number>
	}
}
```

- **logger_name** <span id="logger_name"/> — необязательное переопределение имени logger для этого сайта.

  По умолчанию имя logger создается автоматически, например `log0`, `log1` и так далее, в зависимости от порядка сайтов в Caddyfile. Это полезно только если вы хотите надежно ссылаться на вывод этого logger из другого logger, заданного в глобальных опциях. См. [пример](#multiple-outputs) ниже.

- **hostnames** <span id="hostnames"/> — необязательное переопределение имен хостов, к которым применяется этот logger.

  По умолчанию logger применяется к именам хостов блока сайта, в котором он указан, то есть к адресам сайта. Это полезно, если вы хотите задать разные logger для поддоменов в [блоке сайта с wildcard](/docs/caddyfile/patterns#wildcard-certificates). См. [пример](#wildcard-logs) ниже.

- **no_hostname** <span id="no_hostname"/> не дает связывать logger с какими-либо именами хостов блока сайта. По умолчанию logger связывается с [адресом сайта](/docs/caddyfile/concepts#addresses), в котором находится директива `log`.

  Это полезно, когда вы хотите записывать запросы в разные файлы по какому-либо условию, например по пути или методу запроса, используя [директиву `log_name`](/docs/caddyfile/directives/log_name).

- **output** <span id="output"/> настраивает, куда записывать журналы. См. [модули `output`](#output-modules) ниже.

  По умолчанию: `stderr`.

- **format** <span id="format"/> описывает, как кодировать или форматировать журналы. См. [модули `format`](#format-modules) ниже.

  По умолчанию: `console`, если `stderr` определен как терминал; иначе `json`.

- **level** <span id="level"/> — минимальный уровень записей для журналирования. По умолчанию: `INFO`.

  Обратите внимание, что журналы доступа сейчас создают записи только уровней `INFO` и `ERROR`.

- **sampling** <span id="sampling"/> настраивает семплирование журналов для уменьшения их объема. Если `sampling` указан, семплирование включается и применяются значения по умолчанию ниже. Если опустить этот блок, семплирование отключено.

  - **interval** — [окно длительности](/docs/conventions#durations), в пределах которого выполняется семплирование. По умолчанию: `1s` (отключено).

  - **first** — сколько записей журнала сохранять для данного уровня и сообщения в каждом интервале. По умолчанию: `100`.

  - **thereafter** — сколько записей журнала пропускать в каждом интервале после первых сохраненных записей. По умолчанию: `100`.

  Например, при `interval 1s`, `first 5` и `thereafter 10` в каждом 10-секундном интервале будут сохранены первые 5 записей журнала, затем будет пропускаться каждая запись, кроме каждой 10-й записи с тем же уровнем и сообщением в пределах этой секунды.


<a id="output-modules"></a>
### Модули вывода

Поддиректива **output** позволяет настроить, куда записываются журналы.

<a id="stderr"></a>
#### stderr

Стандартный поток ошибок (консоль, используется по умолчанию).

```caddy-d
output stderr
```

<a id="stdout"></a>
#### stdout

Стандартный поток вывода (консоль).

```caddy-d
output stdout
```

<a id="discard"></a>
#### discard

Без вывода.

```caddy-d
output discard
```

<a id="file"></a>
#### file

Файл. По умолчанию файлы журнала ротируются ("roll") по размеру, чтобы предотвратить исчерпание места на диске.

Ротация журналов предоставляется [timberjack <img src="/old/resources/images/external-link.svg" class="external-link">](https://github.com/DeRuina/timberjack)

<aside class="tip">

**Примечание о перезагрузке опций файлов журнала:** чтобы применить изменения конфигурации к заданному файлу вывода, требуется перезапуск сервера.
Изменения не будут применены при reload сервера, если вы не добавите новое имя файла журнала.

</aside>

```caddy-d
output file <filename> {
	mode          <mode>
	roll_disabled
	roll_size     <size>
	roll_interval <duration>
	roll_minutes  <minutes...>
	roll_at	      <times...>
	roll_uncompressed
	roll_local_time
	roll_keep     <num>
	roll_keep_for <days>
	backup_time_format <format>
}
```

- **&lt;filename&gt;** — путь к файлу журнала.

  При ротации файлы переименовываются по шаблону `<name>-<timestamp>-<reason>.log`. Метка времени форматируется согласно опции [`backup_time_format`](#backup_time_format). Причина — либо `size`, либо `time`, в зависимости от того, что вызвало ротацию. Если файл сжимается, к имени файла добавляется `.gz`.

   Например, если имя файла `access.log`, ротированный файл может называться `access-2026-01-30T22-15-42.123-size.log`, если ротация произошла из-за размера, или `access-2025-01-30T00-00-00.000-time.log`, если ротация произошла по времени.

- **mode** <span id="mode"/> — Unix-режим/права доступа для файла журнала. Режим состоит из 1-4 восьмеричных цифр; это тот же числовой формат, который принимает команда Unix [chmod <img src="/old/resources/images/external-link.svg" class="external-link">](https://en.wikipedia.org/wiki/Chmod), за исключением того, что полностью нулевой режим интерпретируется как режим по умолчанию `600`.

  Например: `0600` задает режим `rw-,---,---` (доступ на чтение/запись для владельца файла журнала и отсутствие доступа для остальных); `0640` задает `rw-,r--,---` (чтение/запись для владельца файла, только чтение для группы); `644` задает режим `rw-,r--,r--`, предоставляя чтение/запись владельцу файла журнала, но только чтение владельцу группы и другим пользователям.

- **roll_disabled** <span id="roll_disabled"/> отключает ротацию журналов. Это может привести к исчерпанию места на диске, поэтому используйте эту опцию только если файлы журналов обслуживаются другим способом.

- **roll_size** <span id="roll_size"/> — размер, при котором файл журнала ротируется. Текущая реализация поддерживает разрешение в мегабайтах; дробные значения округляются вверх до следующего целого мегабайта. Например, `1.1MiB` округляется до `2MiB`.

  Эта опция всегда включена. Если запись в журнал приводит к превышению указанного размера файла, журнал будет немедленно ротирован. В резервном имени файла будет указана причина `size`.

  По умолчанию: `100MiB`

- **roll_interval** <span id="roll_interval"/> — максимальная длительность между ротациями журнала. Значение является [строкой длительности](/docs/conventions#durations), после которой файл журнала должен быть ротирован.

  Когда опция включена, файл ротируется при следующей записи в журнал после того, как эта длительность прошла с момента последней ротации. В резервном имени файла будет указана причина `time`.

  Обратите внимание: если задано `24h`, ротация не обязательно произойдет в полночь; она произойдет через 24 часа после последней ротации. Если ротация произойдет из-за размера, время следующей ротации сместится относительно предыдущей. Чтобы ротировать в определенное время, используйте опции `roll_at` или `roll_minutes`.

  По умолчанию: отключено

- **roll_minutes** <span id="roll_minutes"/> — список значений минут (0-59), в которые нужно ротировать файл журнала. Например, `10 40` будет ротировать файл журнала каждые 30 минут, в `xx:10` и `xx:40` каждого часа. Ротации выравниваются по минуте часов (секунда 0).

  Включение этой опции запускает goroutine-таймер, который инициирует ротацию журнала в указанные значения минут, то есть добавляет небольшой объем фоновой обработки. Это работает вместе с `roll_interval` и `roll_size`. В резервном имени файла будет указана причина `time`.

  По умолчанию: отключено

- **roll_at** <span id="roll_at"/> — список значений времени в 24-часовом формате, когда нужно ротировать файл журнала. Например, `00:00 12:00` будет ротировать файл журнала два раза в день: в полночь и в полдень. Ротации выравниваются по минуте часов (секунда 0).

  Включение этой опции запускает goroutine-таймер, который инициирует ротацию журнала в указанное время, то есть добавляет небольшой объем фоновой обработки. Это работает вместе с `roll_interval` и `roll_size`. В резервном имени файла будет указана причина `time`.

  По умолчанию: отключено

- **roll_uncompressed** <span id="roll_uncompressed"/> отключает gzip-сжатие журналов.

  По умолчанию: сжатие `gzip` включено.

- **roll_local_time** <span id="roll_local_time"/> задает использование локальных меток времени в именах файлов при ротации. 
  По умолчанию: используется время UTC.

- **roll_keep** <span id="roll_keep"/> — сколько файлов журнала сохранять перед удалением самых старых. Срабатывает при создании нового файла журнала.

  По умолчанию: `10`

- **roll_keep_for** <span id="roll_keep_for"/> — как долго хранить ротированные файлы, задается [строкой длительности](/docs/conventions#durations). Срабатывает при создании нового файла журнала.
  Текущая реализация поддерживает разрешение в днях; дробные значения округляются вверх до следующего целого дня. Например, `36h` (1,5 дня) округляется до `48h` (2 дней).
  
  По умолчанию: `2160h` (90 дней)

- **backup_time_format** <span id="backup_time_format"/> — формат времени для имен резервных файлов. Должен быть допустимой строкой макета времени; подробности см. в [документации Go](https://pkg.go.dev/time#pkg-constants).

  По умолчанию: `2006-01-02T15-04-05`


<a id="net"></a>
#### net

Сетевой сокет. Если сокет перестает работать, журналы будут сбрасываться в stderr, пока Caddy пытается переподключиться.

```caddy-d
output net <address> {
	dial_timeout <duration>
	soft_start
}
```

- **&lt;address&gt;** — [адрес](/docs/conventions#network-addresses), куда записывать журналы.

- **dial_timeout** <span id="dial_timeout"/> — как долго ждать успешного подключения к сокету журнала. Если сокет недоступен, отправка записей журнала может блокироваться на срок до этого значения.

- **soft_start** <span id="soft_start"/> будет игнорировать ошибки при подключении к сокету, позволяя загрузить конфигурацию, даже если удаленный сервис журналов недоступен. Вместо этого журналы будут выводиться в stderr.


<a id="format-modules"></a>
### Модули формата

Поддиректива **format** позволяет настроить, как журналы кодируются (форматируются). Она указывается внутри блока `log`.

<aside class="tip">

**Примечание о Common Log Format (CLF):** CLF конфликтует с современными структурированными журналами. Чтобы преобразовать журналы доступа в устаревший Common Log Format, используйте [плагин `transform-encoder` <img src="/old/resources/images/external-link.svg" class="external-link">](https://github.com/caddyserver/transform-encoder).

</aside>


В дополнение к синтаксису каждого отдельного encoder, для большинства encoder можно задавать эти общие свойства:

```caddy-d
format <encoder_module> {
	message_key     <key>
	level_key       <key>
	time_key        <key>
	name_key        <key>
	caller_key      <key>
	stacktrace_key  <key>
	line_ending     <char>
	time_format     <format>
	time_local
	duration_format <format>
	level_format    <format>
}
```

- **message_key** <span id="message_key"/> Ключ для поля сообщения записи журнала. По умолчанию: `msg`

- **level_key** <span id="level_key"/> Ключ для поля уровня записи журнала. По умолчанию: `level`

- **time_key** <span id="time_key"/> Ключ для поля времени записи журнала. По умолчанию: `ts`
- **name_key** <span id="name_key"/> Ключ для поля имени записи журнала. По умолчанию: `name`

- **caller_key** <span id="caller_key"/> Ключ для поля caller записи журнала.

- **stacktrace_key** <span id="stacktrace_key"/> Ключ для поля stacktrace записи журнала.

- **line_ending** <span id="line_ending"/> Используемые окончания строк.

- **time_format** <span id="time_format"/> Формат меток времени.
  По умолчанию: `wall_milli`, если формат по умолчанию стал `console`; иначе `unix_seconds_float`.
  
  Может быть одним из:
  - `unix_seconds_float` Число секунд с плавающей точкой с начала эпохи Unix.
  - `unix_milli_float` Число миллисекунд с плавающей точкой с начала эпохи Unix.
  - `unix_nano` Целое число наносекунд с начала эпохи Unix.
  - `iso8601` Пример: `2006-01-02T15:04:05.000Z0700`
  - `rfc3339` Пример: `2006-01-02T15:04:05Z07:00`
  - `rfc3339_nano` Пример: `2006-01-02T15:04:05.999999999Z07:00`
  - `wall` Пример: `2006/01/02 15:04:05`
  - `wall_milli` Пример: `2006/01/02 15:04:05.000`
  - `wall_nano` Пример: `2006/01/02 15:04:05.000000000`
  - `common_log` Пример: `02/Jan/2006:15:04:05 -0700`
  - Или любая совместимая строка макета времени; подробности см. в [документации Go](https://pkg.go.dev/time#pkg-constants).
  
  Обратите внимание, что части строки формата являются специальными константами макета: поэтому `2006` означает год, `01` — месяц, `Jan` — месяц строкой, `02` — день. Не используйте в строке формата фактические числа текущей даты.

- **time_local** <span id="time_local"/> Журналирует с локальным системным временем вместо UTC по умолчанию.

- **duration_format** <span id="duration_format"/> Формат длительностей.

  По умолчанию: `seconds`.
  
  Может быть одним из:
  - `s`, `second` или `seconds` Число прошедших секунд с плавающей точкой.
  - `ms`, `milli` или `millis` Число прошедших миллисекунд с плавающей точкой.
  - `ns`, `nano` или `nanos` Целое число прошедших наносекунд.
  - `string` Использует встроенный строковый формат Go, например `1m32.05s` или `6.31ms`.

- **level_format** <span id="level_format"/> Формат уровней.

  По умолчанию: `color`, если формат по умолчанию стал `console`; иначе `lower`.
  
  Может быть одним из:
  - `lower` Нижний регистр.
  - `upper` Верхний регистр.
  - `color` Верхний регистр с ANSI-цветами.
  

<a id="console"></a>
#### console

Encoder `console` форматирует запись журнала так, чтобы она была удобна для чтения человеком, сохраняя при этом часть структуры.

```caddy-d
format console
```

<a id="json"></a>
#### json

Форматирует каждую запись журнала как JSON-объект.

```caddy-d
format json
```


<a id="filter"></a>
#### filter

Позволяет фильтровать отдельные поля.

```caddy-d
format filter {
	fields {
		<field> <filter> ...
	}
	<field> <filter> ...
	wrap <encode_module> ...
}
```

На вложенные поля можно ссылаться, обозначая уровень вложенности символом `>`. Иными словами, для объекта вида `{"a":{"b":0}}` внутреннее поле можно указать как `a>b`.

Следующие поля являются базовыми для журнала и не могут фильтроваться, потому что нижележащая библиотека журналирования добавляет их как особые случаи: `ts`, `level`, `logger` и `msg`.

Указывать `wrap` необязательно; если он опущен, значение по умолчанию выбирается в зависимости от того, является ли текущий модуль вывода [`stderr`](#stderr) или [`stdout`](#stdout) и интерактивным терминалом. В этом случае выбирается [`console`](#console), иначе выбирается [`json`](#json).

В качестве сокращения блок `fields` можно опустить и указывать фильтры прямо внутри блока `filter`.


Доступны следующие фильтры:

<a id="delete"></a>
##### delete

Помечает поле так, чтобы оно пропускалось при кодировании.

```caddy-d
<field> delete
```


<a id="rename"></a>
##### rename

Переименовывает ключ поля журнала.

```caddy-d
<field> rename <key>
```


<a id="replace"></a>
##### replace

Помечает поле для замены указанной строкой во время кодирования.

```caddy-d
<field> replace <replacement>
```


<a id="ip-mask"></a>
##### ip_mask

Маскирует IP-адреса в поле с помощью CIDR-маски, то есть числа битов IP-адреса, которые нужно сохранить, начиная слева. Если поле является массивом строк, например HTTP-заголовками, маскируется каждое значение массива. Значение может быть строкой IP-адресов, разделенных запятыми.

Для адресов IPv4 и IPv6 используется отдельная конфигурация, поскольку у них разное общее число битов.

Чаще всего фильтруются поля:
- `request>remote_ip` для клиента, подключившегося напрямую
- `request>client_ip` для разобранного "реального клиента", когда настроена опция [`trusted_proxies`](/docs/caddyfile/options#trusted-proxies)
- `request>headers>X-Forwarded-For`, если сервер находится за reverse proxy

```caddy-d
<field> ip_mask [<ipv4> [<ipv6>]] {
	ipv4 <cidr>
	ipv6 <cidr>
}
```


<a id="query"></a>
##### query

Помечает поле для выполнения одного или нескольких действий, чтобы изменить query-часть поля URL. Чаще всего фильтруется поле `request>uri`.

```caddy-d
<field> query {
	delete  <key>
	replace <key> <replacement>
	hash    <key>
}
```

Доступные действия:

- **delete** удаляет указанный ключ из query.

- **replace** заменяет значение указанного query-ключа на **replacement**. Это удобно для вставки placeholder-значения редактирования: вы увидите, что query-ключ был в URL, но значение скрыто.

- **hash** заменяет значение указанного query-ключа первыми 4 байтами SHA-256-хэша значения, в нижнем шестнадцатеричном виде. Это удобно, чтобы скрыть чувствительное значение, но при этом видеть, отличалось ли значение в каждом запросе.


<a id="cookie"></a>
##### cookie

Помечает поле для выполнения одного или нескольких действий, чтобы изменить значение HTTP-заголовка `Cookie`. Чаще всего фильтруется поле `request>headers>Cookie`.

```caddy-d
<field> cookie {
	delete  <name>
	replace <name> <replacement>
	hash    <name>
}
```

Доступные действия:

- **delete** удаляет cookie с указанным именем из заголовка.

- **replace** заменяет значение указанной cookie на **replacement**. Это удобно для вставки placeholder-значения редактирования: вы увидите, что cookie была в заголовке, но значение скрыто.

- **hash** заменяет значение указанной cookie первыми 4 байтами SHA-256-хэша значения, в нижнем шестнадцатеричном виде. Это удобно, чтобы скрыть чувствительное значение, но при этом видеть, отличалось ли значение в каждом запросе.

Если для одного имени cookie задано много действий, будет применено только первое действие.


<a id="regexp"></a>
##### regexp

Помечает поле для применения замены по регулярному выражению во время кодирования. Если поле является массивом строк, например HTTP-заголовками, замены применяются к каждому значению массива.

```caddy-d
<field> regexp <pattern> <replacement>
```

Используется язык регулярных выражений RE2, включенный в Go. См. [справочник синтаксиса RE2](https://github.com/google/re2/wiki/Syntax) и [обзор синтаксиса regexp в Go](https://pkg.go.dev/regexp/syntax).

В строке замены на группы захвата можно ссылаться как `${group}`, где `group` — имя или номер группы захвата в выражении. Группа захвата `0` — полное совпадение regexp, `1` — первая группа захвата, `2` — вторая группа захвата и так далее.


<a id="hash"></a>
##### hash

Помечает поле для замены первыми 4 байтами (8 шестнадцатеричных символов) SHA-256-хэша значения во время кодирования. Если поле является массивом строк, например HTTP-заголовками, хэшируется каждое значение массива.

Это удобно, чтобы скрыть чувствительное значение, но при этом видеть, отличалось ли значение в каждом запросе.

```caddy-d
<field> hash
```

<a id="append"></a>
#### append

Добавляет поле или поля ко всем записям журнала.

```caddy-d
format append {
	fields {
		<field> <value>
	}
	<field> <value>
	wrap <encode_module> ...
}
```

Это наиболее полезно для добавления информации об экземпляре Caddy, который создает записи журнала, возможно через переменную окружения. Значения полей могут быть глобальными placeholder (например, `{env.*}`), но *не* placeholder на уровне запроса, потому что журналы записываются вне контекста HTTP-запроса.

Указывать `wrap` необязательно; если он опущен, значение по умолчанию выбирается в зависимости от того, является ли текущий модуль вывода [`stderr`](#stderr) или [`stdout`](#stdout) и интерактивным терминалом. В этом случае выбирается [`console`](#console), иначе выбирается [`json`](#json).

Блок `fields` можно опустить и указывать поля прямо внутри блока `append`.



<a id="examples"></a>
## Примеры

Включить журналирование доступа в logger по умолчанию.

Иными словами, по умолчанию это записывает журналы в `stderr`, но это можно изменить, перенастроив logger `default` с помощью [глобальной опции `log`](/docs/caddyfile/options#log):

```caddy
example.com {
	log
}
```


Записывать журналы в файл с ротацией журналов, которая включена по умолчанию:

```caddy
example.com {
	log {
		output file /var/log/access.log
	}
}
```


Настроить ротацию журналов: ежедневно в полночь или когда файл журнала достигнет 1 GB, в зависимости от того, что наступит раньше, и хранить 5 ротированных файлов или журналы за 30 дней:

```caddy
example.com {
	log {
		output file /var/log/access.log {
			roll_at 00:00
			roll_size 1gb
			roll_keep 5
			roll_keep_for 720h
		}
	}
}
```


Удалить заголовок запроса `User-Agent` из журналов:

```caddy
example.com {
	log {
		format filter {
			request>headers>User-Agent delete
		}
	}
}
```


Отредактировать несколько чувствительных cookie. Обратите внимание, что некоторые чувствительные заголовки по умолчанию журналируются с пустыми значениями; см. [глобальную опцию `log_credentials`](/docs/caddyfile/options#log-credentials), чтобы включить журналирование значений заголовка `Cookie`:

```caddy
example.com {
	log {
		format filter {
			request>headers>Cookie cookie {
				replace session REDACTED
				delete secret
			}
		}
	}
}
```


Маскировать удаленный адрес из запроса, сохраняя первые 16 битов, то есть 255.255.0.0, для IPv4-адресов и первые 32 бита для IPv6-адресов.

Обратите внимание, что начиная с Caddy v2.7 журналируются и `remote_ip`, и `client_ip`, где `client_ip` — это "реальный IP", когда настроена опция [`trusted_proxies`](/docs/caddyfile/options#trusted-proxies):

```caddy
example.com {
	log {
		format filter {
			request>remote_ip ip_mask 16 32
			request>client_ip ip_mask 16 32
		}
	}
}
```


Чтобы добавить ID сервера из переменной окружения ко всем записям журнала и объединить это с `filter` для удаления заголовка:

```caddy
example.com {
	log {
		format append {
			server_id {env.SERVER_ID}
			wrap filter {
				request>headers>Cookie delete
			}
		}
	}
}
```


<span id="wildcard-logs" /> Чтобы записывать отдельные файлы журнала для каждого поддомена в [блоке сайта с wildcard](/docs/caddyfile/patterns#wildcard-certificates), переопределяя `hostnames` для каждого logger. Здесь используется [snippet](/docs/caddyfile/concepts#snippets), чтобы избежать повторов:

```caddy
(subdomain-log) {
	log {
		hostnames {args[0]}
		output file /var/log/{args[0]}.log
	}
}

*.example.com {
	import subdomain-log foo.example.com
	@foo host foo.example.com
	handle @foo {
		respond "foo"
	}

	import subdomain-log bar.example.com
	@bar host bar.example.com
	handle @bar {
		respond "bar"
	}
}
```

<span id="multiple-outputs" /> Чтобы записывать журналы доступа для конкретного поддомена в два разных файла с разными форматами: один с [плагином `transform-encoder` <img src="/old/resources/images/external-link.svg" class="external-link">](https://github.com/caddyserver/transform-encoder), другой с [`json`](#json).

Это работает за счет переопределения имени logger как `foo` в блоке сайта, затем включения журналов доступа, созданных этим logger, в два logger в глобальных опциях с помощью `include http.log.access.foo`:

```caddy
{
	log access-formatted {
		include http.log.access.foo
		output file /var/log/access-foo.log
		format transform "{common_log}"
	}

	log access-json {
		include http.log.access.foo
		output file /var/log/access-foo.json
		format json
	}
}

foo.example.com {
	log foo
}
```

<span id="sampling-example" /> Чтобы уменьшить объем журналов с помощью семплирования, например сохранять первые 5 запросов в секунду, затем 1 из каждых 10 последующих запросов:

```caddy
example.com {
	log {
		sampling {
			interval   1s
			first      5
			thereafter 10
		}
	}
}
```
