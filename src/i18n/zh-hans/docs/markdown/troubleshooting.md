故障排除策略
=====================

本页面提供了一个通用且有条理的框架，帮助您在不使用人工智能的情况下，自行解决使用 Caddy 时可能遇到的绝大多数问题。在我们的论坛中寻求帮助时，我们也建议您遵循类似的步骤。在许多情况下，通过运用一些批判性思维，您就能自己解答问题或解决问题。


你懂什么？
-----------------

你可能不知道问题出在哪里、是什么原因导致的，也不知道该如何解决，所以让我们先从一些你肯定了解的基础知识开始：

### 您的期望

大声说出来，或者在心里默念，或者写下来。表达要清晰明确，不要留下任何疑问或模棱两可的余地。你甚至可以向自己解释一下，*为什么*你会抱有这样的期待。

“应该能行”并不是一个合理的预期。

“我预计在向该 URI 发送请求时会收到 301 重定向”这样表述要好得多。


### 当前行为

观察正在发生的事情。究竟发生了什么，这与你的预期有何不同？综合你所了解的情况。

“这行不通”这种说法既无助于解决问题，又显得敷衍；应尽量避免使用这一短语，除非是作为对某项已详细记录的特定行为的简要描述。

“我收到的不是 301 响应，而是 200 响应，尽管我确实看到了 `Server: Caddy` 标头”，这样表述要好得多，因为它将已知情况与预期情况进行了对比，并综合了其他已知信息，这表明请求至少已到达一个 Caddy 实例。


### 日志

Caddy 的日志记录在何处？默认情况下，这些日志会写入启动该进程的终端。如果像系统服务那样以“脱离”模式运行，您可能需要从其他地方获取日志。

请注意，HTTP 请求日志（“访问日志”）与进程日志不同，需要在配置中明确启用。

如果您尚未启用 DEBUG 级别的日志记录，建议您启用该功能。

但无论哪种情况，你首先要做的一件事就是查看日志。*全部日志*。消息上下文至关重要，因此孤立的一行日志通常没什么用。收集比你预想中更多的日志，并在整个故障排除过程中妥善保存。

日志里有任何线索吗？


识别并质疑假设
-------------------------------

在继续之前，我们必须强调，对自己的假设进行批判是多么重要。我们都会根据自己的习惯和预期做出各种假设。“谨记你的假设，你的力量便会无比强大。”（——尤达，大概是这么说的。）

例如，人们通常认为，在重新编译 Caddy 之后，运行 `caddy` 将导致新代码运行。这仅在您的编译二进制文件替换了 `$PATH`。相反， `./caddy` 通常才是正确的调用方式。

随着部署或配置的日益复杂，相关假设也会随之增加。例如，在 Docker 中进行部署涉及重新构建镜像并运行它，这会使您可能做出的假设成倍增加。

许多问题和错误报告最终被发现是外部系统和网络配置的问题，而非 Caddy 本身的问题。例如，如果你无法连接到你的 Caddy 实例，但 Caddy 显然正在运行，你可能会认为这不是 DNS 的问题。提示：这几乎总是 DNS 的问题。

即使只是假设你重新加载了配置文件，而实际上并没有，这也是一种常见的错误。请务必严格遵守流程，在每个环节都进行验证。


重现该现象
----------------------

这是一个关键步骤，往往能让问题自行解决：让问题再次发生。

具体来说，要*以尽可能简化的方式*重现该问题。剔除不必要的配置、部署步骤、环境因素等，直到问题消失。

一种常见的策略是每次只排除一项因素，然后重新尝试，直到问题消失。此时，你所排除的那项因素很可能就是原因；或者——这也是质疑假设的好时机——问题可能是最后一项因素与之前排除的因素的某种组合所导致的。通过重新加入最初被排除的因素来验证，从而逐步缩小范围。

另一种思路是在每次迭代中淘汰大约一半的选项，一旦问题消失，就只淘汰剩余部分的一半，依此类推。这类似于二分搜索，速度可能更快。

或者，与其采用排除法，不如反其道而行之，从头开始逐步构建配置或场景，每次都重新尝试，直到问题出现。

通常，仅通过这一过程就能查明问题所在，解决方案也往往显而易见。如果不行，你至少可以记录下重现该问题的最小步骤。


探索行为
-----------------

既然已经掌握了能够复现该问题的步骤，您就具备了诊断原因的有利条件。这需要进行一些调试，如果您精通技术，还可以阅读代码。

如果你无法解释问题产生的原因，那就尝试改变行为模式。做一点小改动，然后重新尝试。例如，如果相关的配置涉及正则表达式，可以修改或简化该表达式——或者直接将其删除——看看是否能通过某种方式得到你期望的行为。即使结果并非你所期望的，至少你能确定问题出在正则表达式或配置上。

在探索的过程中，请留意哪些方法有效、哪些无效的规律。这应该能引导你找到解决问题的途径。

如果你找到了解决方案，那么你可以判断这是否属于一个错误。有时很难判断是否属于错误；无论结果如何，你都可以提交一个问题，附上你的测试结果，并听取维护者的反馈。

如果这不是一个 bug，那恭喜你！你不仅解决了问题，在这个过程中还学到了不少东西。

不妨[在论坛上](https://caddy.community)分享您的经历，以帮助可能遇到同样问题的其他人。
